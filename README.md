# Trent

Веб-панель для учёта таксопарка в аренде: картотека машин, сроки документов и ТО, платежи по аренде, история ремонтов и отчёты для Telegram.

## Возможности

- Показывает карточки машин: госномер, марку, модель, статус (`В аренде`, `На ремонте`, `Не в аренде`), пробег, номер СТС и собственника.
- Ведёт аренду по дневному, недельному или месячному графику, строит таймлайн платежей за 30 дней, считает просрочку и процент менеджера.
- Записывает ТО и ремонты, где перечисляются запчасти, артикулы и цена работ; любую запись можно поправить во всплывающем окне или удалить.
- Напоминает про сроки ОСАГО, техосмотра, лицензии такси, КАСКО и планового ТО по дате и пробегу.
- Хранит список водителей с историей аренд и показывает, кто на какой машине сейчас ездит.
- Собирает еженедельные, ежемесячные и годовые отчёты по всему парку, одной машине или собственнику в обычном тексте и в Markdown для Telegram.
- Переключает светлую и тёмную тему по настройке системы или вручную, работает на экранах шириной от 360 px.

На главной странице открывается сводка за месяц и 30 дней: сколько аренды оплатили, сколько заработал менеджер, какой накопился долг, сколько ушло на ремонт и у каких машин подходят сроки. Если нажать на карточку, откроются подробные данные, таймлайн платежей и история ремонтов.

На странице управления машиной администратор редактирует общие поля, вносит документы и план ТО, настраивает аренду с комиссией менеджера, добавляет или правит ремонты и при необходимости удаляет машину.

В разделе отчётов выбирают период, машину или собственника, а также нужные блоки: финансы, ремонты или оба сразу. Готовый текст копируется в буфер обмена одной кнопкой.

## Роли и безопасность

Права проверяются на сервере: API сверяет сессию и отвечает `401` или `403`, а закрытые страницы не пускают пользователей без нужной роли.

- `admin` работает со всем парком, меняет машины, водителей, учётные записи и отчёты.
- `owner` открывает только свои машины и отчёты по ним, без права что-то менять.
- `viewer` смотрит общий дашборд и отчёты, не заходит в управление и список пользователей.

Пароли хэшируются через Node `crypto.scrypt` с 16-байтной случайной солью и сверяются через `timingSafeEqual`. Сессии лежат в SQLite, а токен уходит в `HttpOnly` cookie с `SameSite=Lax` (в production добавляется `Secure`). Когда администратор меняет роль или пароль пользователя, его активные сессии сбрасываются. Последнего администратора и свою собственную учётную запись удалить нельзя.

SQLite работает в режиме `WAL` при включённом `foreign_keys = ON`. Когда приложение стартует, оно само прогоняет идемпотентные миграции схемы с версии 1 по версию 4.

## Запуск

Локально нужен Node.js 20 или новее:

```sh
npm ci
npm run db:seed
npm run dev
```

Чтобы собрать и запустить production-версию локально:

```sh
npm run build
npm start
```

Команда `npm run db:seed` добавляет тестовые учётные записи: `admin` (`admin123`), `viewer` (`viewer123`) и `owner` (`owner123`). Перед выходом в реальную работу эти пароли стоит поменять.

Для запуска через Docker Compose:

```sh
docker compose up -d --build
```

Контейнер `trent-backend` слушает порт `127.0.0.1:3000`, кладёт SQLite-файл в `./data:/app/data` (`DATABASE_URL=/app/data/taxi.db`), работает в поясе `Europe/Moscow` и проверяет готовность по адресу `/login`.

## Разработка

Стек проекта: Next.js 15 (App Router), React 19, TypeScript, Tailwind CSS v4, Drizzle ORM (`better-sqlite3`), Zod, Vitest и Testing Library.

Перед коммитом прогоните четыре команды:

```sh
npm run lint
npx tsc --noEmit
npm test
npm run build
```

Интерфейс штрафов сейчас скрыт флагом `SHOW_FINES = false` в `src/lib/features.ts`, хотя таблицы базы данных, провайдер `FinesProvider` и API-маршруты остались на месте. По умолчанию данные хранятся в SQLite, а схема описана в `src/db/schema.ts`.
